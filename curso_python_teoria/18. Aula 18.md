##### Recursividade e Funções Recursivas

Funções recursivas são funções que chamam a si mesmas. Elas são úteis quando temos um problema grande e podemos dividir o problema em partes menores.

As funções recursivas devem ter as seguintes características:

-  Um problema que possa ser dividido em partes menores;
-  Um caso recursivo que resolve um pequeno problema;
-  Um caso base que para a recursão
-  Exemplo de problema: fatorial de um número n qualquer.

```Python
def recursiva(inicial=0, fim==10):
	# Caso recursivo
	# Contar até o final
	inicio += 1
	return recursiva(inicio, fim)
```

O caso base, é o caso de parada e ele é importante de ser definido para evitarmos de ocasionar algum "stack overflow" que funciona como se fosse uma "boneca russa", ou seja, uma chamada de função dentro da outra. 

Em resumo, é como se cada chamada de função fosse "mais interna" sem ter um fim. 

A melhor maneira de corrigir o erro que está no código acima (ele ocasiona stack overflow) é utilizando um caso base ou caso de parada.

```Python
def recursiva(inicial=0, fim=10):  
    # Caso recursivo  
    # contar até chegar ao final  
    if inicial >= fim:  
        return fim  
  
    inicial += 1  
    return recursiva(inicial, fim)  
  
print(recursiva())
```

Quando finalmente a minha função encontra o caso base, ela vai retornando os valores e removendo as chamadas da call stack (pilha de chamadas)

Em Python, o limite de recursão é de 1000, ou seja, mais do que isso a linguagem não suporta e lança uma exceção de "RecursionError" no terminal (mesmo que o programa esteja correto), como o caso da contagem de 1 a 1000.

Para resolver isso eu posso alterar o limite de recursão usando a biblioteca sys. 

```Python
import sys
sys.setrecursionlimit(1004)
```

##### Ambientes virtuais

Os ambientes virtuais no Python, de forma simples, são "pastas" e nessa pasta é onde temos a instalação do Python e tudo que estiver junto com o Python.

![[Pasted image 20250112095216.png]]

Toda a instalação, incluindo biblioteca de terceiros vão para essa pasta. 

Os ambientes virtuais servem como uma forma de organizar os mesmos projetos. Por exemplo.

Imagine que exista um desenvolvedor web que possui dois clientes, um dos clientes deseja um site sobre bolsa de valores, mercado e bitcoins. Já o outro é um site de noticias sobre games, séries e cultura nerd. 

-  No primeiro vão ser necessárias funcionalidades que não se tem necessidade no segundo e é a partir disso que dividimos os projetos em ambientais virtuais distintos. Para evitar acumulo de módulo e pacotes que não vão ser usados em um determinado projeto.

-  Um bom ponto é que com o ambiente virtual (venv), como se trata de uma pasta, caso seja necessário dar manutenção em um código depois de muito tempo passado, a pasta venv contém todas as versões dos módulos e bibliotecas utilizados.

===Obs: não há necessidade de enviar a pasta/módulo venv para o repositório, pois nos criamos um arquivo chamado=== *requirements.txt* ===que serve para informar o que foi usado naquele determinado projeto, para que mais na frente eu possa informar ao Python para instalar tudo que está no requirements.txt===

Nomes comuns usados em ambientais virtuais.

-  venv, env, .venv e .env (o . em sistemas unix faz com que a pasta fique oculta), pode ser passado também um diretório de um ambiente virtual já existente.
##### Criando um ambiente virtual

```cmd
diretorio> python -m venv venv
```

-  -m - executa uma library que tem no Python como script (executa no próprio prompt de comando);
-  venv é o nome da library;
-  venv (de novo) é o nome do ambiente virtual.

![[Pasted image 20250112101902.png]]

Após ser criado o ambiente virtual terá as seguintes pastas.

-  Include; 
-  Lib - pasta em que ficam todas as bibliotecas de terceiros que forem instaladas
-  Scripts - possui todos os executáveis que forem necessários de serem usados no ambiente virtual, como por exemplo 
	-  O arquivo "activate" que serve para ativar o ambiente virtual
	-  O comando "deactivate" desativa o venv.
	-  O pip que é o instalador de pacotes do Python, é com eles que instalamos bibliotecas
	-  E os executáveis do Python.

O Python base fica separado do Python que será usado para executar os projetos, esse será o que está na pasta Scripts.

===Obs: um fato curioso é que quando usamos o comando "python" no prompt de comando o sistema busca nas variáveis de ambiente o local em que o Python foi instalado===

Para ativar o ambiente virtual, basta ir direto no activate através do prompt.

```cmd
D:\Josue\Cursos\python\testando_venv> ambiente\Scripts\activate
(ambiente) D:\Josue\Cursos\python\testando_venv>

# para desativar
(ambiente) D:\Josue\Cursos\python\testando_venv> deactivate
```

##### pip - instalando e desinstalando pacotes

O pip é um instalador de pacotes do Python que instala pacotes do PyPi.org

Exemplo instalando PyMySQL

```cmd
pip install pymysql
pip uninstall pymysql
```

Para listar todos os pacotes instalados executar o comando

```cmd
pip freeze
```

Para ver todas as versões disponíveis de um pacote eu posso usar o seguinte comando

```cmd
pip index versions "nome do pacote"
```

Para atualizar ou alterar a versão basta que eu utilize um valor de igual

```cmd
pip install pymysql==1.0.2
```

E por fim, para atualizar para última versão, basta dar um upgrade

```CMD
pip install pymysql --upgrade
```

##### Criando arquivo requirements.txt

Um arquivo requirements.txt nada mais é do que um arquivo de texto que informa todas as bibliotecas que estão sendo usadas no projeto, juntamente com suas versões.

Para criar o arquivo requirements.txt usamos o comando abaixo

```CMD
pip freeze > requirements.txt
```

-  Agora supondo que eu não possua um pasta chamada venv, baixei o repositório do github e ele está apenas com o requirements.txt, o que fazer?

	 Com o ambiente virtual ativo, para executar a instalação dos pacotes eu faço

```CMD
pip install -r requirements.txt
```

Caso alguma outra lib seja adicionada, basta eu atualizar o arquivo requirements.txt usando o penúltimo comando visto.
