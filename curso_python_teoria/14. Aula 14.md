##### Import, from, as e *

O Python possui vários módulos padrão, como por exemplo o módulo sys, os, pathlib e entre outras que podem ser conferidas por meio desse link

```markdown
https://docs.python.org/3/py-modindex.html
```

Existem vantagens e desvantagens de usar uma determinada maneira de importar um módulo Python.

-  Importando módulo inteiro

```Python
import nome_modulo
import sys

print(sys.plataform)
```

| **                      Vantagem** | **                       Desvantagem**            |
| ---------------------------------- | ------------------------------------------------- |
| Temos acesso ao namespace completo | nomes muito grande, dificuldade para se trabalhar |

-  Importando partes de um módulo

```Python
from nome_modulo import obj1, obj1
from sys import platafor, exist
```

| **                 Vantagem                     ** | **                           Desvantagem                          ** |
| -------------------------------------------------- | -------------------------------------------------------------------- |
| Nomes pequenos                                     | Sem o namespace do módulo                                            |
Nesse caso é importante saber que se houver alguma variável criada no programa que possua o mesmo nome que algum elemento que eu esteja importando, o que está sendo importado é sobrescrito.

-  Importando e alterando o nome do módulo

```Python
import sys as s
sys = "alguma coisa"
print(s.platform)
```

Da mesma maneira que coloquei um apelido em um módulo inteiro, eu posso fazer com elementos específicos, assim como fiz com o from. 

```Python
from sys import platform as pt, exist as ex
```

| **                     Vantagens**                                | **                       Desvantagens**                                        |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Você pode reservar nomes para variáveis e elementos do seu código | As modificações podem ficar fora do padrão normalmente adotado pela linguagem. |
===O último é uma má prática de programação, que é quando importamos tudo usando * ===

```Python
from sys import *
```

##### Modularização - Entendendo os seus próprios módulos sys.path do Python

Modularização é quando separamos o código de forma que ele fique mais legível e organizado. Pois se fizéssemos tudo em um único arquivo ficaria incompreensível.

-  Podemos organizar módulo dentro de pacotes. (Pacotes funcionam como pastas)

O primeiro módulo executado pelo Python quando começamos a trabalhar com modularização é o:  **__ main __** o nome do módulo está disponível ao chamar 
**__ name __**

-  Podemos importar um outro módulo inteiro, ou parte dele (porém, o nome deve ser diferente dos módulos já existentes no Python). ===Ou seja, se eu criar um módulo chamado sys, eu enfrentarei um problema caso eu queira usar também a biblioteca padrão sys===

O Python reconhece arquivos que quero importar e que estão na mesma pasta do main, desde que estejam abaixo dele, porém, se fosse em pastas acima ou externas, eu deveria procurar pelo diretório. Ele não reconhece pastas e módulos acima do __ main __ por padrão

*Em resumo, o Python reconhece as pastas mais internas, porém, não as mais externas ao módulo.*

```Python
print(* sys.path, sep="\n")`
```

A pasta **"site-packages"** lista as bibliotecas instaladas por fora do Python. 

-  Eu poderia adicionar diretórios a esse path seguindo o procedimento abaixo. 

```Python
sys.path.append("\home")
```

O Python ia procurar arquivos na pasta home.

Em resumo, temos o seguinte

-  o *sys.path* retorna uma lista com os caminhos/diretórios;
-  se o diretório em que está meu módulo não estiver aparecendo, eu posso usar um append;
-  com o append eu adiciono o diretório que desejo e finalmente conseguirei usar o que necessitar.

##### Como importar coisas do seu próprio módulo (ponto de vista do __ main __ )

O (seu) main é o ponto de entrada do programa. A partir daí eu posso criar pastas (pacotes) e módulos, porém todos irmãos do main. 

```Python
# arquivo de módulo
variavel_modulo = 'Josue'
```

```Python
# arquivo main

# importando tudo
import modulo_teste

# importanndo somente a variavel
from modulo_teste import variavel_modulo

print(variavel_modulo)
```

===Lembrando que o Python só consegue encontrar módulos e pacotes irmãos ou que seja interiores, para encontrar alguma coisa externa deve ser feita manipulação no=== *sys.path*

##### Recarregando módulos, importlib e singleton

- Os módulos que importamos na programação são **singletons**, ou seja, só pode existir uma única instância daquele 'objeto' no programa inteiro. Então dessa forma, como já importamos no começo, por questão de eficiência o Python não importa outras vezes.

```Python
import teste_modulo  
  
print(teste_modulo.variavel_modulo)  
  
for i in range(10):  
    import teste_modulo  
    print(i)  
print("fim")
```

Normalmente não fazemos recarregamento de módulos, porém caso haja necessidade de utilizar, fazemos isso com **importlib**

```Python
import importlib

import teste_modulo

print(teste_modulo.variavel_modulo)  
  
for i in range(10):  
    # Recarregando o módulo
    importlib.reload(teste_modulo) 
    print(i)  
print("fim")
```

##### Introdução aos Packages em Python

-  Os pacotes (pastas) devem possuir os mesmos nomes dos módulos;
-  ===Dica: crie um main, e na pasta raiz que contém o main você cria o restante dos pacotes necessários===;
-  O import package não faz nada;

Método para importar pacotes (pastas) para a main

```Python
from teste_modulo_package.modulo import soma_do_modulo
```

```Python
from nome_do_pacote_pasta.nome_do_modulo_py import nome_da_funcao_ou_constante

# ou entao

import teste_modulo_package.modulo # namespace inteiro

# ou ainda

from teste_modulo_package.modulo import modulo

# má prática

from teste_modulo_package import * 
```

-  Eu ainda posso modificar a forma que um pacote envia o "all" ao ser "solicitada" a importação de um módulo. Para isso, basta que eu defina no módulo o que será representado como all. 

> Exemplo

```Python
# arquivo main

from teste_modulo_package.modulo import *
# tudo do módulo "modulo" sera importado
```

Definindo o que seria representado como tudo no módulo "modulo".

```Python
# arquivo/módulo "modulo" que está na pasta teste_modulo_package

__all__ = [
	"variavel",
	"soma_numeros"
]

variavel = "Alguma coisa"

PI = 3.1415

def soma_numeros(x, y):
	return x + y

def printa_msg(msg):
	print(msg)
```

Quando temos um package com vários módulos dentro dele em que um utiliza uma função ou constante do outro e decidimos importar para a main, segue abaixo uma esquematização.

```MARKDOWN
|->> packages
	|>> modulo.py
	|>> modulo_b.py
|
|->> main.py
```

Por exemplo, *modulo.py* e *modulo_b.py*  compartilham dados entre si, funções e constantes. 

- Se modulo.py importou modulo_b.py ele conseguirá executar no modulo.py corretamente.
- Porém, se modulo.py importou modulo_b.py e em seguida minha main.py importou o modulo.py. E main não conseguirá acessar o que for de modulo_b.py

Isso ocorre pelo seguinte motivo. 

1.  Estamos analisando o projeto como um todo a partir do arquivo principal (main);
2.  Quando a main tenta importar o modulo.py ela encontra um erro, pois um arquivo secundário (modulo.py) está tentando fazer importações de outros arquivos secundários (modulo_b.py). 
3.  Como a importação no modulo.py está sendo feita do tipo abaixo, ele não encontra o arquivo, já que ele está dentro de um pacote. 

```Python
from modulo_b import fala_oi
```

===Obs: todas as importações devem estar relacionadas com o main===

Para consertar isso, basta na módulo que será usado, usar também o nome do pacote.

```Python
from teste_modulo_package.modulo_b import fala_oi
```

Os packages (pastas) em Python podem ser inicializados com arquivos chamados 
**__ init __ 

Vimos anteriormente que importando apenas o package não conseguimos fazer nada, uma vez que ele serve apenas para organização dos nossos módulos. 

```Python
import teste_modulo_package
# não faz nada
```

O arquivo __ init __ que está dentro de um package é executado assim que o módulo é importado. Dessa maneira, qualquer coisa que eu insira no __ init __ será executada assim que a main iniciar.

```Python
# arquivo __init__ do package teste_modulo_package
print("voce esta executando o ", __name__)

def dobra(x):
	return x * 2
```

```Python
import teste_modulo_package

# executando apenas esse import ele vai printar o print que fiz no __init__

# S:
# voce esta executando o teste_modulo_package
```

Porém da forma que está acima, como fizemos uma função dentro do __ init __ podemos tratar o package como se fosse um módulo também.  Ou seja, podemos chamar a função dobra a partir do package. Veja o exemplo abaixo.

```Python
import teste_modulo_package  
  
print(teste_modulo_package.dobra(2))
```

Como o próprio nome já diz, eu posso informar no __ init __ todas as funções e constantes necessárias  que eu desejo utilizar, da seguinte forma.

```Python
# arquivo __init__

from teste_modulo_package.modulo import soma_numeros, PI  
# EU PODERIA TER USADO TBM COM O PONTO  
from .modulo import soma_numeros, PI

# arquivo main

import teste_modulo_package  
  
print(teste_modulo_package.soma_numeros(3, 5))
```

Basicamente, o __ init __ serve como uma forma de transformarmos um package em um módulo para executar funções e constantes. 

- ===Obs: a situação em que eu poderia usar o * poderia ser para essa transformação de packages em módulos.===

```Python
# arquivo __init__
from teste_modulo_package.modulo import *
```
