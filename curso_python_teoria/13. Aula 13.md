##### dir, hasattr e getattr em Python

Uma coisa muito comum em Python quando estamos tratando de objetos é verificar determinadas coisas. Além disso, normalmente usamos no modo interativo ou debugger.

```Python
string = "Luiz"
dir(string)
```

-  o dir trás todos os atributos e métodos que estão definidos dentro da classe string

```Python
string = "Luiz"
if hasattr(string, "upper"):
	print("possui o método")
	print(string.upper())

# sintase
# hasattr(objeto, nome_do_metodo_ou_atributo)
```

- hasattr checa se um objeto tem um determinado nome lá dentro (atributo/método).
	Ainda podemos chamar dinamicamente, segue o exemplo. 

	```Python
	string = "Luiz"
	metodo = "upper"

	if hasattr(string, metodo):
		print("Existe upper")
```

Porém, dessa maneira, armazenando o nome do método a ser verificado em uma variável, não há como executar o método dessa forma.

```Python
string.metodo() # Não vai funcionar.
```

A partir disso entra outro método importante que é o getattr.

-  getattr verifica e reconhece caso existe um método ou atributo presente em um determinado objeto. 

```Python
print(getattr(string, metodo)) 
# informa se o método existe e o local do objeto na memória
```

Se o método existir podemos executar ele diretamente através do getattr(), basta acrescentar os parenteses novamente. 

```Python
# executando um método existente usando getattr()
print(getattr(string, metodo)())
```

===Obs: apenas métodos que não necessitam parâmetros===

##### Generator Expression

Generator são bem específicos do Python, em outras linguagens existem algumas semelhanças. Além disso, é importante saber que todo *Generator* é um *Iterator*, porém, um *Iterator* não é um *Generator*

-  **Generator**: são funções que sabem *"pausar"*.
-  **Iterator**: são uma classe que deve ter os métodos iter e next e trabalham junto à um iterável.

```Python
generator = [n for n in range(10000)]
```

Exemplo de uso do generator, é quando estamos trabalhando com muitos dados e queremos ir fazendo o procedimento aos poucos.

-  Exemplo de generator expression em Python.

```Python
import sys

generator = (n for n in range(10000))
print(generator)

# sys.getsizeof(obj)  -> tamanho em bytes na memoria
print(sys.getsizeof(lista))
print(sys.getsizeof(generator))
```

Parece uma tuple comprehension, *(o que não faz sentido, já que tuplas são imutáveis)*

-  O tamanho da lista na memoria aumenta se aumentarmos a quantidade de valores, já o do generator permanece

	 Porém, o generator não está na memória por completo, por esse motivo não sei o tamanho dele, o primeiro, não se pode indexar e entre outros procedimentos que fazemos nas listas.

##### Introdução às Generator Functions em Python

Vimos que uma função geradora em Python, pode ser do tipo

```Python
# Expressao e não função
generator = (n for n in range(1000000))
```

E sabemos também que uma função geradora em Python significa que ela tem como característica principal o fato de conseguir "*pausar*" a execução.

```Python
def generator(n=0):  
    yield 1
```

A diferença das funções normais (que tem o *return*) para as generator functions, (que tem uma pausa na execução) é que as generator ao invés de usar o clássico return, vão usar a palavra chave *yield*.

-  A função clássica do return em funções simples será feita pela yield nas generator functions;
-  O return normal nessas funções vai funcionar como se fosse um raise, ou seja, o return vai levantar uma exceção de *StopIteration*;
-  Para cada yield "retornado" eu tenho um método "next" associado.

```Python
def generator(n=0):  
    yield 1 # ele pausa aqui  
    print("Continuando....")  
    yield 2 # pausa novamente  
    print("Mais uma vez...")  
    yield 3  
    print("Vou terminar")  
    return "ACABOU"  
  
gen = generator(n=0)  
print(gen.__iter__())  
print(next(gen))  
print(next(gen))  
print(next(gen))  
print(next(gen))


# Posso colocar em um for 
gen = generator(n=0)  
for n in gen:
	print(n)

# SAÍDA
# 1
# Continuando....
# 2
# Mais uma vez...
# 3
# Vou terminar
```

Vimos no começo do curso que um **while True** pode ser pausado através de um comando de input(). Porém, o mesmo pode ser feito se definirmos o laço dentro e uma generator function. 

```Python
def generator_2(n=0, maximum=10):  
    while True:       
	    yield n  
		 n += 1
		 if n >= maximum:
			 return
  
gen_2 = generator_2()  
for n in gen_2:  
    print(n)
```

##### yield from em generator functions

Podemos colocar funções generator correlacionadas.

```Python
def gen1():  
    yield 1  
    yield 2  
    yield 3  
  
def gen2():  
    yield from gen1()  
    yield 4  
    yield 5  
    yield 6  
  
g = gen2()  
  
for numero in g:  
    print(numero)
```

Segue abaixo um exemplo de funções generator que dependem uma da outra, semelhante as funções padrão.

```Python
def gen1():  
    print("COMECOU GEN 1")  
    yield 1  
    yield 2  
    yield 3  
    print("ACABOU GEN 1")  
  
def gen3():  
    print("COMECOU GEN 3")  
    yield 10  
    yield 20  
    yield 30  
    print("ACABOU GEN 3")  
  
  
def gen2(gen):  
    print("COMECOU GEN 2")  
    yield from gen()  
    yield 4  
    yield 5  
    yield 6  
    print("ACABOU GEN 2")  
  
g = gen2(gen1)  
g2 = gen2(gen3)  
  
for numero in g:  
    print(numero)  
  
for numero in g2:  
    print(numero)
```

##### Try, except, else e finally

Vamos relembrar um pouco sobre try-except-finally.

-  O try tenta executar um código.
-  O except lança uma exceção/erro no terminal (ela pode ser escolhida através do programador)
-  O finally ... 

==Obs: sempre o try deve estar acompanhado, ou com um except ou finally. Lembrando sempre que como forma de uma boa prática de programação, o except deve ser especificado. ===

```Python

# Má prática de programação, não estou indicado qual o erro, ele está sendo silenciado.

try:
	...
except:
	...
```

No exemplo abaixo, podemos ver que o programa leva uma exceção ao tentar dividir um número por zero. Porém, ele poderia levantar outras exceções. Caso um dos valores, a ou b não fossem definidos, o erro seria "NameError", pois uma das variáveis não foi definida. 

```Python
# Try, except, else e finally  
  
# a = 18  
# b = 0  
  
# levanta exceção de divisão por zero  
# c = a / b  
  
try:  
    a = 18  
    b = 0  
    print("Linha1")  
    c = a / b  
    print("Linha2")  
except:  
    print("Dividiu por 0")  
  
print("CONTINUAR")
```

Em Python, existe uma classe chamada Exception e todas as outras exceções herdam dessa classe.

```Python

# Consertando o código acima e tratando alguns erros

try:  
    a = 18  
    b = 0  
    print("Linha1")  
    c = a / b  
    print("Linha2")  
except ZeroDivisionError:  
    print("Dividiu por 0")  
except NameError:  
    print("Uma das variáveis não foi definida")  
except TypeError:  
    print("O tipo não é float ou inteiro")  
  
print("CONTINUAR")
```

Sabendo disso, podemos tratar a classe Exception, para que não apareça qualquer tipo de erro, porém, não saberemos o erro em específico para ser tratado.  Podemos também passar tratar duas exceções em uma única linha, basta inseri-las em uma tupla.

```Python
try:  
    a = 18  
    b = 0  
    print("Linha1")  
    print(b[0])  
    c = a / b  
    print("Linha2")  
except ZeroDivisionError:  
    print("Dividiu por 0")  
except NameError:  
    print("Uma das variáveis não foi definida")  
except (TypeError, IndexError):  
    print("O tipo não é float ou inteiro / Indíce inválido")  
except Exception:  
    print("Erro desconhecido")  
  
# Caso eu não queira erro nenhum, eu posso tratar a classe base das classes de exceções  
  
print("CONTINUAR")
```

Certo, mas e se eu não sei o nome da exceção e eu desejo obter o nome, como eu faço?
Basta fornecer um alias para a exceção e printar ela.

```Python
except (TypeError, IndexError) as error:
	print("MSG:", error)
	print("Nome do erro/Classe do erro: ", error.__class__.__name__)
```

Porém, nesse caso o "*error*" vem com a mensagem do erro e não o nome dele em si. 

-  .__ class ___ : retorna a classe exata a qual o objeto pertence.
- .__ name __ : retorna o nome da classe

##### mais sobre try, except e finally

Caso eu não queira verificar erros, eu posso usar um bloco em combinação com o try, chamado de finally, que sempre será executado. 

Exemplo:

```Python
# Para o finally, vamos exemplificar no ato de ocorrer um erro ao abrir um arquivo  
  
try:  
    print("ABRIR O ARQUIVO")  
    8/0  
    # open  
finally:  
    # sempre é executado  
    print(2)  
    print("FECHAR ARQUIVO")  
  
# O finally executa mesmo se tiver erros
```

Além disso, eu poderia acrescentar um except para tratar o erro de divisão por zero

```Python
try:  
    print("ABRIR O ARQUIVO")  
    8/0  
    # open 
except ZeroDivisionError:
	print("Dividiu por zero")
finally:  
    # sempre é executado  
    print(2)  
    print("FECHAR ARQUIVO") 
```

Como o finally é sempre executado, em aplicações que as vezes ocorrem erros ele pode ser bastante eficiente. Como por exemplo

-  Abri um arquivo, porém, ele está corrompido ou será necessário fechar.
-  Solicitou uma conexão de rede, porém será necessário finalizar ela.

Além da combinação de try-except, try-finally e try-except-finally, podemos ter com else, também. 

```Python
try:
	print("ABRIR ARQUIVO")
	# 8/0
except ZeroDivisionError:
	print("Dividiu por zero")
else:
	print("Código ocorreu sem erros")
finally:
	print("FECHAR ARQUIVO")
```

##### raises - lançando exceções (erros)

O erro na programação é lançado quando não há mais o que fazer. No caso da divisão por zero, por exemplo, não há uma resposta que o Python possa entregar, pois não existe.

```Python
print(123)
raise ValueError("Deu Erro")
```

A sintaxe de construção de erros é bem simples, basicamente usamos a palavra chave raise e em seguida a classe da exceção que queremos junto ao parenteses que recebe a mensagem que será passada para o console. 

```Python
raise Classe("Mensagem")
```

Erros são importantes, pois ajudam na legibilidade e entendimento do código para outros programadores e para você mesmo. 

Nos casos em que não quero suprimir o erro, em que eu desejo reenviar o erro eu utilizo o raise ===(Casos em que estamos falando do erro em um except)===. 

```Python

def divide(n, d):
	try:
		return n / d
	except ZeroDivisionError:
		print("------")
		raise

# Porém o except com raise ao invés do return é redundante
# Não teria necessidade de um except
print(divide(8, 0))
```

O caso acima, só será viável caso seja necessário fazer algum código dentro do bloco do except que está o raise

-  Obs: podemos usar try aninhados.

Exemplo de usando e criando raises. 

```Python
def nao_aceita_zero(d):  
    if d == 0:  
        raise ZeroDivisionError("Você está tentando dividir por zero")  
    return True  
  
def deve_ser_int_ou_float(n):  
  
    tipo_n = type(n)  
  
    if not isinstance(n, (float, int)):  
        raise TypeError(  
            f"{n} deve ser int ou float. "            
            f"{tipo_n.__name__} enviado")  
    return True  
  
  
def divide(n, d):  
  
    deve_ser_int_ou_float(n)  
    deve_ser_int_ou_float(d)  
    nao_aceita_zero(d)  
    return n / d  
  
  
print(divide(8, "0"))
```
